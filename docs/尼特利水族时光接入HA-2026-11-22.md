> **渐变时长已实测生效**（2026-11-22 晚）：主灯 `fade_on` 设 10 分钟后开灯，肉眼可见"灯开了但明显偏暗 → 十来分钟后才到最亮"；关灯同理。帧回帧（cmd20）**始终显示目标值**（R39 G24 W50 B32 F130 不变），因为渐变发生在驱动/PWM 层，协议层看不到中间值——所以只能靠观感验证，不能靠回帧。
> 出厂值：主灯 60/60（分钟）；射灯/氛围灯是 `00 01`（16 位小端读=256，疑似"无渐变/按秒"的标记位，未定标）。注意 `0` 会被设备钳成 `1`。

### 行程写入示例（HA 服务 mqtt.publish 或脚本里调用）

主灯（含 5 通道光谱、modeId、grade）：

```json
{"sunMoonDisable":0,"sunTime":0,"moonTime":0,
 "trips":[{"tripDisable":0,"weekCycle":127,
           "startH":8,"startM":0,"endH":20,"endM":0,
           "R":39,"G":24,"W":50,"B":32,"F":130,"modeId":1,"grade":4}]}
```

射灯（只有 moodLamp + grade）：

```json
{"trips":[{"tripDisable":0,"weekCycle":127,"startH":9,"startM":0,
           "endH":21,"endM":0,"moodLamp":60,"grade":0}]}
```

氛围灯（topic `netlea/tank_atmo/trip/set`，布局同射灯，走 cmd31）：

```json
{"trips":[{"tripDisable":1,"weekCycle":127,"startH":18,"startM":0,
           "endH":22,"endM":0,"moodLamp":58,"grade":0}]}
```

主灯若要按"行程"语义下发，额外带 `"tripMode":1`（对应帧头 byte4 置 1，与 APP 点「提交预设行程」一致）：

```json
{"tripMode":1,"trips":[...]}
```

- 最多 10 段，缺省段自动补 0。
- `weekCycle` 是星期位掩码（127 = 每天，见 APP 的周循环）。
- `tripDisable`=1 表示该段被禁用（不会再写入后立即生效）。
- **写行程后立即生效**：设备会立刻按新行程判定当前时刻该亮还是该灭，实测写完不在时段内主灯当场就关了。改完记得检查灯的状态。

## 四、命令表（逆向自官方 XAPK 明文 app-service.js，逐条实测）

| 命令 | 方向 | 用途 |
|---|---|---|
| `0x05` cmd5 | 下发 | **灯具初始化**⚠️ 会重载设备存储状态（把刚关的灯重新点亮），禁止用于轮询 |
| `0x15` cmd21 | 下发 | **查询状态（安全）**，只回一帧 cmd20 |
| `0x10` cmd16 | 下发 | 主灯实时设置 `lampState｜lampMode｜r1｜r2｜R｜G｜W｜B｜F｜restore(2B)｜modeId｜grade(2B)｜r3｜r4` |
| `0x1A` cmd26 | 双向 | 主灯配置读回/写入 `on(2B)｜off(2B)｜R｜G｜W｜B｜F｜modeId｜grade(2B)`。**grade 只有这条能持久化** |
| `0x11` cmd17 | 下发 | 射灯实时设置 `lampState｜lampMode｜r1｜r2｜moodLamp｜restore(2B)｜grade｜r3` |
| `0x1C` cmd28 | 双向 | 射灯配置 `on(2B)｜off(2B)｜moodLamp｜grade`（射灯 grade 靠这条写） |
| `0x1E` cmd30 | 下发 | 氛围灯实时设置（同 cmd17 布局，需 followType=0 手动才被接受） |
| `0x20` cmd32 | 双向 | 氛围灯配置 `on(2B)｜off(2B)｜moodLamp｜grade` |
| `0x22` cmd34 | 下发 | 氛围灯跟随 `followType｜channel｜grade`（0手动/1随主灯亮/2主灯灭时亮） |
| `0x16` cmd22 | 下发 | **射灯跟随** `followType｜channel｜grade`（同 cmd34 布局，实测 follow 1↔0 生效，写后射灯会被置亮/灭） |
| `0x1B` cmd27 | 下发 | 读主灯配置 → 回 cmd26 |
| `0x1D` cmd29 | 下发 | 读射灯配置 → 回 cmd28 |
| `0x21` cmd33 | 下发 | 读氛围灯配置 → 回 cmd32 |
| `0x25` cmd37 | 下发 | 按**位掩码**读：`[7]`=一次全读（bit0→cmd18 主灯行程、bit1→cmd19 射灯行程、bit2→cmd31 氛围灯行程），`[0]`→cmd32、`[3]`→cmd25 |
| `0x12` cmd18 | 双向 | 主灯行程：`sunMoonDisable(1B)｜sunTime(2B)｜moonTime(2B)｜10×(12字段+grade2B)`；帧头 byte4 = **tripMode**（APP 提交行程时置 1） |
| `0x13` cmd19 | 双向 | 射灯行程：`10×(tripDisable,weekCycle,startH,startM,endH,endM,moodLamp,grade)` |
| `0x1F` cmd31 | 双向 | 氛围灯行程：布局与 cmd19 完全相同（10 段 × 8 字节） |
| `0x14` cmd20 | 上报 | 状态：master 13B@0、spot 9B@13、atmo 9B@22（GRP 里 followType 在偏移 7） |

补充：
- 帧头 0x5A：`[0x5A, len, devType=1, cmd, 0, 0, payload…, sum]`，`len = 总字节+1`，`sum = 全部字节和 %256`。
- 多字节字段一律**小端**（JS 里 `Jo()` 会反转字节）。
- `lampMode`：0 手动 / 3 行程运行 / 4 临时开关；临时开关配 `restoreActTime`，**0 = 立刻恢复**。
- 氛围灯**有独立行程**（cmd31，需 cmd37 `[4]` 或 `[7]` 读），不是只能跟随主灯。

## 五、踩过的坑（不要重犯）

1. **cmd5 不是查询**，是初始化，当轮询用会不停把灯"复活"。
2. **厂商云一个账号只允许一条 WS 连接**：另开测试连接会把常驻桥接踢下线，现象是"HA 点了没反应 + 实体 unavailable"。所有调试走 `netlea/tank_light/debug/send`。
3. **氛围灯默认 followType=1（随主灯）**，此时直控帧被静默丢弃，要先发 cmd34 切手动。
4. **grade 用 cmd16/17/30 写不进去**（读回原值），必须走 cmd26/28/32。
5. HA 的 JSON 灯光命令里 `state` 与 `brightness` 同时出现，解析不能写 if/elif。
6. `brightness_scale: 100` 让 HA 下发 0–100，设备 `moodLamp` 也是 0–100，可直传。
7. **写行程/写配置后设备会立刻按新值动作**：写完全在时间窗外的行程，主灯当场变 `R0 G0 W0 B0 F0`（看着像"灯坏了"，其实是行程判定灭灯）。要恢复就重新写一遍 cmd16 带原光谱。
8. **光谱 5 个通道要逐个写，但相邻两次间隔 ≥1.5s**，间隔太短设备会漏吞中间的（实测 0.6s 间隔时 W/B 丢，1.5s 全中）。
9. **APP 里的"行程"有两种状态**：只是加在列表里还没点「提交预设行程 / 一键导入行程」时，云端/APP 有记录但设备里是 0 段（cmd37 `[7]` 读回来全空）。要让 HA 读到，必须先在 APP 提交。

## 八、APP 侧行程与设备侧的对应关系（2026-11-22 实测结论）

- APP「行程」页里加了时段（例如 7 段、13:02–15:32 等），但**没有点「提交预设行程」之前，设备里是 0 段**——cmd37 `[7]` 读回来 cmd18/cmd19/cmd31 三段全空，HA 的 `sensor.netlea_*_trip` 显示"未设置"。
- 行程对象在 JS 里同时带 `power`（界面显示的 W 数）和 `grade/dangwei`（真正下发的"档位"）；**进帧的只有 grade，瓦数只是界面展示**。
- 「提交预设行程」时 JS 会给帧头 byte4 置 `tripMode=1`，即该段行程才算"行程"而非临时光谱。
